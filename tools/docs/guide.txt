links each to the previous and next one. Its first page is the site's landing page. Every line of text: is indented
by two spaces; its small markup (## heading, - list, 1. numbered, > tip, ! warning, ``` code ```, `code`, **bold**,

Lua syntax is explained once, on the page "lua basics", for beginners who know logic but not syntax; the other pages link there instead of repeating it
(jft 2026-11-22: heavily compact, no repeats). also: keeps the addresses of older, merged pages working (the old Lua

lead: Make VS Code know every Lullaby name: it suggests them while you type, shows what they do, and underlines mistakes before you reload. Done once, about five minutes.
text:
  ## What you install
  - **VS Code**: a free program for writing code.
  - **The Lua extension**: teaches VS Code the Lua language.
  - **lullaby.d.lua**: a list of every Lullaby name with its description, made from this site. Only the editor reads it; Lullaby never runs it.

  ## Steps
  1. **Install VS Code.** Go to code.visualstudio.com, click the big download button, run the installer, open VS Code.
  2. **Add Lua.** Click the icon of four squares on the far left (or press `Ctrl+Shift+X`). Type `Lua` into the search box. Click the result called **Lua** by **sumneko**, then the blue **Install** button.
  3. **Open the Lullaby folder.** Menu **File → Open Folder…**. Go into your server folder (the one with `paper.jar`), then `plugins`, click `lullaby` once and press **Select Folder**. If VS Code asks whether you trust the authors, click **Yes**. The left side now shows `scripts` and `config.lua`.
    No `lullaby` folder? Start the server once with the Lullaby jar in `plugins`; it makes the folder.
  4. **Download the list.** Click here: [download lullaby.d.lua](lullaby.d.lua). Your browser saves it in your **Downloads** folder.
  5. **Put it next to config.lua.** Open your Downloads folder, drag `lullaby.d.lua` into VS Code and drop it on the empty space on the left, **below** the files (not on `scripts`). It now shows next to `config.lua`.
  6. **Tell VS Code which Lua.** Right-click the empty space on the left, **New File…**, type `.luarc.json` (with the dot in front), press Enter. Into the empty file paste `{ "runtime.version": "LuaJIT" }` and save with `Ctrl+S`. Without this, VS Code marks some correct code as wrong.

  The left side now shows: `scripts`, `.luarc.json`, `config.lua`, `lullaby.d.lua`.

  ## Check it
  Right-click `scripts`, **New File…**, name it `test.lua`. Type `mess`: a small list pops up with `message`. Press Enter, then point the mouse at `message`: its description appears. Delete `test.lua` afterwards (right-click, **Delete**), or the next reload runs it.
  Nothing happens? Press `Ctrl+Shift+P`, type `Reload Window`, press Enter, try again.

  > After a Lullaby update, do steps 4 and 5 again and replace the old file.

  Make `scripts/hello.lua`:
  ```
  -- /hello greets whoever types it
  command{ "hello", function(c)
    message{ player = c.player, text = "Hello, " .. c.player.name .. "!" }
  end }
  ```
  Type `/lullaby reload` (green: loaded; red: an error), then `/hello`.
  - `command{ "hello", function(c) ... end }` adds /hello; the function runs each time someone types it. `c.player` is who typed it.
  - `message{ player = ..., text = ... }` sends a chat message.
  The file's top level runs once while loading; functions inside run later, when something happens. Every symbol here (`--`, `..`, `function`, `end`) is explained on the next page.

  ## Reading the docs
  - `{ }` **does** something (copper): `message{ player = p, text = "Hi" }`, fields by name.
  - `( )`, `.` and `:` only **read** (teal): `player("Notch")`, `p.name`.
  - Gold is a type, violet an event, pale blue a field name, bold is Lua itself. Every colored name is a link.
  - On a page: **Arguments** is what you give, **Fields** what you can read, **For experts** can be skipped.

--[[doc
id: lua
name: lua basics
kind: guide
group: Guide
also: guide_lua guide_variables guide_if guide_loops comments values nil true false numbers strings and or not local tables methods if then else elseif while repeat until for in do break goto function return end varargs closures error string_lib table_lib math_lib metatables locked io os ffi debug require
words: lua syntax grammar basics variable local value table list number text string nil true false if then else elseif condition loop for while repeat until forever ipairs pairs break goto continue function return comment operator equal join length string table math random floor format insert remove sort concat metatable setmetatable
lead: All of Lua's grammar on one page: how to write variables, lists, if, loops and functions so Lua understands them.
text:
  ## Writing code
  - A block starts with a word and closes with `end`: `if ... then` ... `end`. Every `if`, `for`, `while` and `function` needs its own `end`; a missing one is the most common error (it points to the end of the file).
  - Indent the inside by two spaces so you see what belongs where. Lua ignores it; you won't.
  - Capitals matter: `Message` is not `message`. Text needs quotes: `"hello"`, `'hello'` (or `[[...]]` over many lines). `\n` is a line break.
  - `--` starts a comment to the end of the line (`--[[ ... ]]` over many lines). Lua skips it; write notes there.

  ## Variables
  ```
  local coins = 10            -- make a variable and set it
  coins = coins + 5           -- change it (no "local" again)
  local a, b = 1, 2           -- several at once
  ```
  Always write `local` the first time: the variable then belongs to the block it is in (file, function, if, loop). `nil` means "nothing here": an unset variable is `nil`.

  ## Operators
  - Math: `+ - * /`, `%` remainder, `^` power. `7 / 2` is `3.5`; `math.floor(7 / 2)` is `3`.
  - Compare: `==` equal, `~=` not equal, `< > <= >=`. **One `=` stores, two compare**: `if x = 5` is an error.
  - Logic: `and`, `or`, `not`. Only `nil` and `false` count as false; `0` and `""` are true. `x or 5` gives x, or 5 when x is nil: a default.
  - Text: `..` joins two texts, `#` is the length.

  ## Lists and tables
  ```
  local list = { "a", "b", "c" }     -- a list, counted from 1
  print(list[1], #list)              -- the first item, the length
  list[#list + 1] = "d"              -- add to the end
  local spawn = { x = 0, y = 64 }    -- named fields
  spawn.z = 0                        -- same as spawn["z"] = 0
  local kills = {}
  kills[p] = (kills[p] or 0) + 1     -- anything can be a key, even a player
  ```
  `v:offset(1, 0, 0)` with `:` calls a method on a value; it is short for `v.offset(v, 1, 0, 0)`.

  ## if
  ```
  if hp >= 15 then
    print("healthy")
  elseif hp >= 5 then                -- optional, as many as you like
    print("hurt")
  else                               -- optional
    print("help!")
  end
  ```

  ## Loops
  ```
  for i = 1, 10 do print(i) end              -- 10 times, i counts 1 to 10
  for i = 10, 1, -1 do print(i) end          -- count down (third number: the step)
  for i, p in ipairs(online_players()) do    -- each item of a list, in order
    print(i, p.name)
  end
  for key, value in pairs(spawn) do end      -- each field of a table, any order
  while x < 10 do x = x + 1 end              -- as long as true; checks before each round
  repeat x = x - 1 until x <= 0              -- until true; checks after: runs at least once
  ```
  Forever is `while true do ... wait(1) ... end`: always wait inside, or the script is stopped. `break` leaves a loop. Lua has no `continue`: write `goto continue` and put `::continue::` right before the loop's `end`.

  ## Functions
  ```
  local function add(a, b)           -- define
    return a + b                     -- give a value back and leave
  end
  local sum = add(2, 3)              -- use: 5
  local function two() return 1, 2 end
  local x, y = two()                 -- several results at once
  local function all(...) return #{ ... } end   -- ... takes any number of values
  ```
  A function is a value: `on{ }`, `command{ }` and `run{ }` take one, usually written right there as `function(e) ... end`. A function inside another still sees that one's local variables later. `error("text")` stops with a red message; [pcall( )](#pcall) catches it.

  ## Ready-made functions
  - Text: `s:upper()`, `s:lower()`, `s:sub(1, 5)` (letters 1 to 5), `s:find("x")`, `s:gsub("a", "b")` (replace), `s:rep(3)`, `string.format("%d coins", 5)`, `tostring(5)`, `tonumber("5")`.
  - Lists: `table.insert(t, v)`, `table.remove(t, i)`, `table.sort(t)`, `table.concat(t, ", ")` (list to one text).
  - Math: `math.random(1, 6)` (a random whole number), `math.floor`, `math.ceil`, `math.abs`, `math.min`, `math.max`, `math.sqrt`, `math.pi`.
  - Other: `print(x)` (to the server window), `type(x)`, `pairs`, `ipairs`, `select`, `unpack`, `setmetatable` (own classes; most scripts never need it).
  Locked for safety, so they don't exist in scripts: `io`, `os`, `ffi`, `debug`, `require`. They can be unlocked in `config.lua` under `unlock`; use [import( )](#import) for your own files.
expert: LuaJIT | Lullaby runs LuaJIT, which speaks Lua 5.1 plus goto. Newer Lua (//, bit operators like &, utf8, <const>) doesn't exist; bit.band and friends do. Numbers are doubles, whole numbers exact up to 2^53. # counts bytes: "ä" has length 2. Lua patterns (find, match, gsub) are not regex: %d digit, %a letter, %s space, % escapes, no | and no {n}.
expert: Isolation | every script file has its own globals and its own copy of string, table, math, coroutine and bit. getmetatable on a Lullaby value (player, vec3, ...) gives false, so no script can change how everyone's values behave. load and loadstring take Lua text only, never bytecode (broken bytecode can crash LuaJIT).
expert: Unlock | unlock.debug also brings jit, collectgarbage, gcinfo, getfenv, setfenv and newproxy: they reach into the Lua state all scripts share. unlock.java opens the [Java door](#java). config.lua is read again on /lullaby reload.
expert: Time limit | a loop running longer than script_time_limit (config) stops with a red error at its next call into the game (message{ }, p.name, ...); final still runs. A loop that never calls into the game (pure math) can't be stopped; after twice the limit the console names what is stuck. A loop that waits never hits the limit.
expert: Cost | arithmetic and one round of a compiled loop: about 1 ns (measured: 1,000,000,000 additions in 0.8–1.1 s). The time-limit check costs nothing per round. A new table or closure: guess 50–300 ns plus garbage collection (not measured). table.concat is the fast way to join many texts; .. in a loop is slow.

id: guide_problems
name: when it goes wrong
kind: guide
group: Guide
words: error errors mistake mistakes debug debugging problem help fix red message line nil attempt to index concatenate common
lead: Every error names the file and the line. Go there, read the message, check the values on that line.
text:
  Not sure what a value is? `print(x)` writes it to the server window, `print(type_of(x))` says what sort it is. One file's error stops only that file.
  - **attempt to index a nil value**: a dot on something empty, like `c.player.name` from the console. Check `if p then` first.
  - **attempt to concatenate a nil value**: `..` got nil.
  - **{ } vs ( )**: `message(p, "Hi")` fails, `message{ player = p, text = "Hi" }` works.
  - **Event names**: `PlayerJoinEvent`, exactly so.
  - **No reload**: saving alone does nothing.
  - **Stopped after 5 seconds**: longer than `script_time_limit` (config). To run long, wait between rounds ([waiting](#guide_waiting)).

id: guide_events
name: events
kind: guide
group: Guide
words: event events on after listener join break block cancel cancelled handler e fields happen
lead: Run code when something happens in the game, and change or stop it.
text:
  ```
  after{ "PlayerJoinEvent", function(e)
    message{ player = e.player, text = "Welcome, " .. e.player.name }
  end }

  on{ "BlockBreakEvent", function(e)
    if e.block.state == block_state("diamond_ore") then
      e.cancelled = true                 -- the block stays
    end
  end }
  ```
  - **after{ }** runs once it happened; it can only look.
  - **on{ }** runs before; it can change fields (`e.cancelled = true`, `e.exp_to_drop = 50`).
  - `e` holds the event's fields. Each event's page (the **Events** group) lists them. A wrong field name is an error that lists the right ones.
  - The dot before an event: gray untested, copper tested and changeable, teal tested read only, ring not usable yet.

--[[doc
id: guide_waiting
name: waiting and tasks
kind: guide
group: Guide
also: guide_memory
words: wait delay later seconds ticks task tasks run stop final schedule timer repeat every countdown cooldown save memory reload lost forever
lead: wait( ) pauses your code while the game goes on. Handlers and commands may wait; run{ } starts more.
text:
  ```
  local function countdown(p)
    for i = 3, 1, -1 do
      message{ player = p, text = tostring(i) }
      wait(1)                            -- 1 second; also "10t", "2s", "5m"
    end
  end
  command{ "go", function(c) run{ countdown, args = { c.player }, id = c.player } end }

  run{ function()                        -- every 2 seconds, forever
    while true do
      for _, p in ipairs(online_players()) do
        particle{ player = p, particle = "heart", pos = p.pos + vec3(0, 2.2, 0) }
      end
      wait("2s")
    end
  end }
  ```
  - `id =` allows one running task per id: a simple cooldown.
  - `final = function() ... end` runs whenever the task ends; `stop{ task = t }` ends one.
  - After a wait, check `p.online`.
  - Reload and restart run every file from the top again: variables reset and tasks end. Scripts can't save their own data yet.

--[[doc
id: guide_together
name: a mini game
kind: guide
group: Guide
words: example project minigame complete full script kill counter zombie hunt game round
lead: A 60-second zombie hunt, using every page before.
text:
  ```
  -- scripts/hunt.lua
  local running, score = false, {}

  local function tell_all(text)
    for _, p in ipairs(online_players()) do message{ player = p, text = text } end
  end

  local function round()
    running, score = true, {}
    tell_all("Zombie hunt! 60 seconds, go!")
    wait("60s")
    local best, most = nil, 0
    for p, n in pairs(score) do if n > most then best, most = p, n end end
    tell_all(best and (best.name .. " wins with " .. most) or "Nobody got a zombie")
  end

  command{ "hunt", function(c)
    if not running then run{ round, final = function() running = false end } end
  end, permission = "hunt.start" }

  after{ "EntityDeathEvent", function(e)
    if not running or e.entity_type ~= "zombie" then return end
    local killer = e.damage_source.causing
    if killer and type_of(killer) == "player" then score[killer] = (score[killer] or 0) + 1 end
  end }
  ```
  `final` resets `running` even after an error or reload. Not counting? `print(e.entity_type)` shows the real name.
  Try: skeletons for two points, `/hunt score`, a sound for the winner.
