id: guide_setup
name: setup
kind: guide
group: Guide
also: guide_server guide_editor
words: test server local install paper java setup localhost eula op editor vscode autocomplete lullaby.d.lua luarc
lead: A private test server on your own computer, and an editor that knows Lullaby.
text:
  ## Test server
  Never test on the server your players use.
  1. Install Java 25. Download Paper for the Minecraft version at the top of the side list, put it in an empty folder as `paper.jar`.
  2. Start it with `java -Xms2G -Xmx2G -jar paper.jar nogui`. Set `eula=true` in `eula.txt`, start again.
  3. Build Lullaby (`gradlew build`, jar in `build/libs`), put the jar in `plugins`, restart.
  4. Join `localhost`, then type `op YourName` in the server window. Ops see script errors in chat.

  Scripts go in `plugins/lullaby/scripts`. Every `.lua` file there loads; a name starting with `--` switches a file or folder off. Settings are in `plugins/lullaby/config.lua`.

  ## Editor
  1. Install VS Code and its **Lua** extension (by sumneko). Open the folder `plugins/lullaby`.
  2. Download `lullaby.d.lua` from this site (its address with `lullaby.d.lua` instead of `#...`) and put it in `plugins/lullaby`, **not** in `scripts`.
  3. Add a file `.luarc.json` there with `{ "runtime.version": "LuaJIT" }`.
  Now the editor completes Lullaby's names and underlines mistakes. Download the file again after a Lullaby update.

--[[doc
id: guide_first
name: your first script
kind: guide
group: Guide
also: guide_docs
words: first script hello world command reload try colors syntax legend doing reading braces brackets
lead: A command that greets you, and how to read the docs.
text:
  Make `scripts/hello.lua`:
  ```
  -- /hello greets whoever types it
  command{ "hello", function(c)
    message{ player = c.player, text = "Hello, " .. c.player.name .. "!" }
  end }
  ```
  Type `/lullaby reload` (green: loaded; red: an error), then `/hello`.
  - `--` starts a comment: ignored by Lullaby.
  - `command{ "hello", function(c) ... end }` adds /hello; the function runs each time someone types it. `c.player` is who typed it.
  - `message{ player = ..., text = ... }` sends a chat message. `..` joins texts.
  The file's top level runs once while loading; functions inside run later, when something happens.

  ## Reading the docs
  - `{ }` **does** something (copper): `message{ player = p, text = "Hi" }`, fields by name.
  - `( )`, `.` and `:` only **read** (teal): `player("Notch")`, `p.name`.
  - Gold is a type, violet an event, pale blue a field name, bold is Lua itself. Every colored name is a link.
  - On a page: **Arguments** is what you give, **Fields** what you can read, **For experts** can be skipped.

--[[doc
id: guide_problems
name: when it goes wrong
kind: guide
group: Guide
words: error errors mistake mistakes debug debugging problem help fix red message line nil attempt to index concatenate common
lead: Every error names the file and the line. Go there, read the message, check the values on that line.
text:
  Not sure what a value is? `print(x)` writes it to the server window, `print(type_of(x))` says what sort it is. One file's error stops only that file.

  ## Common mistakes
  - **Missing end**: every `function`, `if`, `for`, `while` needs one. The error then points to the end of the file.
  - `=` stores, `==` compares, `~=` is "not equal".
  - **attempt to index a nil value**: a dot on something empty, like `c.player.name` from the console. Check `if p then` first.
  - **attempt to concatenate a nil value**: `..` got nil.
  - **Capitals matter**: `PlayerJoinEvent`, not `playerjoinevent`.
  - **{ } vs ( )**: `message(p, "Hi")` fails, `message{ player = p, text = "Hi" }` works.
  - **No reload**: saving alone does nothing.

  A script running longer than `script_time_limit` (5 seconds, config) is stopped with an error. To run long, wait between rounds ([waiting](#guide_waiting)).
status: unconfirmed
]]

--[[doc
id: guide_lua
name: lua basics
kind: guide
group: Guide
also: guide_variables guide_if guide_loops
words: variable local value table list number text nil true false if then else elseif condition loop for while ipairs pairs break
lead: Variables, tables, if and loops: the Lua you need for most scripts.
text:
  ```
  local coins = 10                     -- a variable; always write local the first time
  coins = coins + 5
  local name = "Steve"                 -- text; .. joins, # is the length
  local list = { "a", "b", "c" }       -- a list, counted from 1: list[1], #list
  local spawn = { x = 0, y = 64 }      -- named fields: spawn.y
  local kills = {}
  kills[p] = (kills[p] or 0) + 1       -- per player; "x or 0": x, or 0 when x is nil
  ```
  `nil` means "nothing here". Only `nil` and `false` count as false; `0` counts as true.

  ## if
  ```
  if hp >= 15 then
    message{ player = p, text = "healthy" }
  elseif hp >= 5 then
    message{ player = p, text = "hurt" }
  else
    message{ player = p, text = "help!" }
  end
  ```
  Compare with `== ~= < > <= >=`, combine with `and`, `or`, `not`. `return` leaves a function early.

  ## Loops
  ```
  for _, p in ipairs(online_players()) do   -- once per online player
    message{ player = p, text = "Hi all" }
  end
  for i = 1, 5 do print(i) end              -- 1 to 5
  for p, n in pairs(kills) do print(p.name, n) end
  ```
  `break` leaves a loop. More: [values](#values), [tables](#local), [if and loops](#if).

--[[doc
id: guide_events
name: events
kind: guide
group: Guide
words: event events on after listener join break block cancel cancelled handler e fields happen
lead: Run code when something happens in the game, and change or stop it.
text:
  ```
  after{ "PlayerJoinEvent", function(e)
    message{ player = e.player, text = "Welcome, " .. e.player.name }
  end }

  on{ "BlockBreakEvent", function(e)
    if e.block.state == block_state("diamond_ore") then
      e.cancelled = true                 -- the block stays
    end
  end }
  ```
  - **after{ }** runs once it happened; it can only look.
  - **on{ }** runs before; it can change fields (`e.cancelled = true`, `e.exp_to_drop = 50`).
  - `e` holds the event's fields. Each event's page (the **Events** group) lists them. A wrong field name is an error that lists the right ones.
  - The dot before an event: gray untested, copper tested and changeable, teal tested read only, ring not usable yet.

--[[doc
id: guide_commands
name: commands
kind: guide
group: Guide
words: command commands arguments args permission branches sub subcommand player integer text suggest tab complete optional
lead: Arguments, permissions and sub commands; Lullaby checks every value before your code runs.
text:
  ```
  command{ "dice", function(c)
    local sides = c.args.sides or 6
    message{ player = c.player, text = "You rolled " .. math.random(1, sides) }
  end, args = { { name = "sides", type = "integer", min = 2, max = 100, optional = true } },
  permission = "fun.dice" }
  ```
  - Argument types: `word`, `text` (rest of the line, last only), `integer`, `number`, `bool`, `player`. Read them as `c.args.<name>`.
  - `optional = true` (only at the end), `suggest = { ... }` for tab completion.
  - `branches = { buy = { function(c) ... end, args = { ... } } }` makes `/shop buy ...`.
  - `c.player` is nil in the console.
  Everything else: [command{ }](#command).
status: unconfirmed

--[[doc
id: guide_waiting
name: waiting and tasks
kind: guide
group: Guide
also: guide_memory
words: wait delay later seconds ticks task tasks run stop final schedule timer repeat every countdown cooldown save memory reload lost
lead: wait( ) pauses your code while the game goes on. Handlers and commands may wait; run{ } starts more.
text:
  ```
  local function countdown(p)
    for i = 3, 1, -1 do
      message{ player = p, text = tostring(i) }
      wait(1)                            -- 1 second; also "10t", "2s", "5m"
    end
  end
  command{ "go", function(c) run{ countdown, args = { c.player }, id = c.player } end }

  run{ function()                        -- every 2 seconds, forever
    while true do
      for _, p in ipairs(online_players()) do
        particle{ player = p, particle = "heart", pos = p.pos + vec3(0, 2.2, 0) }
      end
      wait("2s")
    end
  end }
  ```
  - `id =` allows one running task per id: a simple cooldown.
  - `final = function() ... end` runs whenever the task ends; `stop{ task = t }` ends one.
  - After a wait, check `p.online`.

  ## Reload forgets
  Reload and restart run every file from the top again: variables reset and tasks end. Scripts can't save their own data yet.

id: guide_functions
name: functions and files
kind: guide
group: Guide
words: function functions reuse return import file files module folder shared library helper
lead: Write code once, use it everywhere.
text:
  ```
  -- scripts/shared/util.lua
  local util = {}
  function util.greet(p, word)
    message{ player = p, text = word .. ", " .. p.name .. "!" }
  end
  return util
  ```
  ```
  -- scripts/welcome.lua
  local util = import("shared/util")
  after{ "PlayerJoinEvent", function(e) util.greet(e.player, "Welcome") end }
  ```
  `local function name(a, b) ... return x end` makes a function. Each file has its own variables, so files can't break each other; share by returning a table and using `import( )` (path from `scripts`, no `.lua`). More: [functions](#function), [import( )](#import).

--[[doc
id: guide_together
name: a mini game
kind: guide
group: Guide
words: example project minigame complete full script kill counter zombie hunt game round
lead: A 60-second zombie hunt, using every page before.
text:
  ```
  -- scripts/hunt.lua
  local running, score = false, {}

  local function tell_all(text)
    for _, p in ipairs(online_players()) do message{ player = p, text = text } end
  end

  local function round()
    running, score = true, {}
    tell_all("Zombie hunt! 60 seconds, go!")
    wait("60s")
    local best, most = nil, 0
    for p, n in pairs(score) do if n > most then best, most = p, n end end
    tell_all(best and (best.name .. " wins with " .. most) or "Nobody got a zombie")
  end

  command{ "hunt", function(c)
    if not running then run{ round, final = function() running = false end } end
  end, permission = "hunt.start" }

  after{ "EntityDeathEvent", function(e)
    if not running or e.entity_type ~= "zombie" then return end
    local killer = e.damage_source.causing
    if killer and type_of(killer) == "player" then score[killer] = (score[killer] or 0) + 1 end
  end }
  ```
  `final` resets `running` even after an error or reload. Not counting? `print(e.entity_type)` shows the real name.
  Try: skeletons for two points, `/hunt score`, a sound for the winner.
