Lua pages of the docs site (read by Docs.java, same block format as in lib/*.lua; each block names itself with id:).
Lullaby runs LuaJIT, which speaks Lua 5.1 (plus goto). A page is linked from its id and from every word in also:
(Lua keywords such as if or for, and old page names, so old links still land).

--[[doc
id: start
name: start here
kind: lua
group: Lua
also: comments
words: begin first tutorial hello new comment note remark
syntax: -- a comment to the end of the line    --[[ a comment over many lines ]]
lead: A script is a .lua file in plugins/lullaby/scripts. Lullaby runs every file there on start and on /lullaby reload. Code at the top of a file runs once while loading; functions given to on{ }, after{ }, command{ } and run{ } run later, when something happens. Everything after -- is a comment and does nothing; --[[ starts a comment over many lines, ]] ends it.
example:
  -- plugins/lullaby/scripts/hello.lua
  after{ "PlayerJoinEvent", function(e)
    message{ player = e.player, text = "Welcome!" }
    wait("2s")
    sound{ player = e.player, sound = "entity.player.levelup", source = "player", entity = e.player }
  end }
expert: LuaJIT | Lullaby runs LuaJIT (through LuaJava), which speaks Lua 5.1 plus goto. Lua 5.2+ features (integer division //, bit operators &, utf8 library, <const>) don't exist; bit.band and friends do.
expert: Loading | every file gets its own globals: a global in one file is invisible in the others. One file's error stops only that file; import( ) uses what another file returns.
expert: Cost | loading a small file: guess 0.1–2 ms per file (not measured).
status: unconfirmed
]]

--[[doc
id: values
name: values: nil, true, numbers, text
kind: lua
group: Lua
also: nil true false numbers strings and or not
words: boolean null none empty bool math plus minus divide modulo power arithmetic text concat join length quote logic default string
syntax: nil   true   false   + - * / % ^   == ~= < > <= >=   "text" .. "text"   #text   a and b   a or b   not a
lead: nil means "no value": unset variables and missing table fields are nil. true and false are the booleans; in if and while only nil and false count as false, 0 and "" count as true. Lua has one number type for whole numbers and decimals; % is the remainder, ^ the power, ~= means "not equal". Text goes in double or single quotes (or [[ ]] over many lines); .. joins two texts, # gives the length, \n is a line break. In Lullaby a text is always literal text. and is true when both sides are, or when one side is, not turns it around; x or 5 gives x, or 5 when x is nil or false.
example:
  local p = player("Notch")
  if p == nil then print("not online") end
  local half = 7 / 2            -- 3.5
  local rest = 7 % 2            -- 1
  local hello = "Hello, " .. "Steve" .. "!"
  print(#hello)                 -- 13
  local amount = arg or 1       -- a default
  if not p.online and amount > 0 then return end
expert: LuaJIT | numbers are doubles: whole numbers are exact up to 2^53. 1/0 is inf, 0/0 is nan (nan ~= nan). Texts are byte strings: # counts bytes, so "ä" has length 2.
expert: Cost | arithmetic and comparisons: about 1 ns each once LuaJIT compiled the loop (measured: 1,000,000,000 additions in 0.8–1.1 s). Joining texts with .. makes a new text each time: guess 50–500 ns, more for long texts (not measured).
status: unconfirmed
]]

--[[doc
id: local
name: variables and tables
kind: lua
group: Lua
also: tables methods
words: variable var name assign global table list array map dictionary method colon dot self
syntax: local name = value   { 1, 2, 3 }   { key = value }   t[k]   t.key   #t   v:method(...)
lead: A variable holds a value. local makes it belong to the block it is written in (a file, a function, an if, a loop); always use local. Without local it is a global of this script file. A table is Lua's only container: written with numbers it is a list, counted from 1; with names it holds named fields. t.key is short for t["key"], #t is the length of a list. : calls a method on a value: v:offset(1, 0, 0) is short for v.offset(v, 1, 0, 0). In Lullaby, reading uses ( ), . and :, and doing uses { }.
example:
  local count = 0
  count = count + 1
  local a, b = 1, 2            -- several at once
  local list = { "a", "b", "c" }
  print(list[1], #list)        -- a  3
  list[#list + 1] = "d"        -- add to the end
  local spawn = { x = 0, y = 64 }
  spawn.z = 0
  local up = vec3(1, 64, 1):offset(0, 1, 0)
expert: LuaJIT | a function can have at most 200 locals; # of a list with holes (nil in the middle) can give any border. Tables are passed by reference: two variables can hold the same table.
expert: Cost | reading a local: under 1 ns; a table field: about 1–5 ns (guess, not measured); a global: a little slower than a local, so loops prefer locals. A new table: guess 50–200 ns plus garbage collection later (not measured).
status: unconfirmed
]]

--[[doc
id: if
name: if and loops
kind: lua
group: Lua
also: then else elseif while repeat until for in do break goto
words: condition then else elseif when check loop repeat until count number step pairs ipairs each list table iterate stop exit label jump continue skip
syntax: if cond then ... elseif cond then ... else ... end   while cond do ... end   repeat ... until cond   for i = first, last, step do ... end   for k, v in pairs(t) do ... end   break   goto name ::name::
lead: if runs a block only when the condition is true (not nil or false); elseif and else are optional. while repeats as long as the condition is true and checks before each round; repeat ... until checks after each round, so it runs at least once. for i = first, last counts both ends included (step is optional, default 1, may be negative). for ... in ipairs(list) goes through a list in order and stops at the first nil; pairs goes through every field of a table in no fixed order. break leaves the innermost loop; goto jumps to a label in the same function, mostly to skip to the next round (Lua has no continue).
example:
  if count > 10 then print("many")
  elseif count > 0 then print("some")
  else print("none") end

  for i = 10, 1, -3 do print(i) end       -- 10 7 4 1
  for i, p in ipairs(online_players()) do
    if p.name == "Notch" then break end
    if i == 3 then goto continue end
    message{ player = p, text = "Hi #" .. i }
    ::continue::
  end
  for key, value in pairs({ a = 1, b = 2 }) do print(key, value) end
expert: LuaJIT | the for counter is a copy: changing i inside the loop doesn't change the counting. pairs' order can differ between runs; never rely on it.
expert: Time limit | a loop that runs longer than script_time_limit (config) is stopped with a normal red error at its next call into the game (message{ }, p.name, ...); its final still runs. A loop that never calls into the game (pure math) can't be stopped: LuaJIT's compiled loops ignore outside signals; after twice the limit the console names what is stuck. A loop that waits (wait("1t") inside run{ }) never hits the limit.
expert: Cost | one round of a compiled loop with one addition: about 1 ns (measured: 1,000,000,000 rounds in 0.8–1.1 s). The time-limit check costs nothing per round (a flag checked only at calls into the game).
status: unconfirmed
]]

--[[doc
id: function
name: functions
kind: lua
group: Lua
also: return varargs closures error
words: function def define call parameter argument result give back multiple values varargs dots select upvalue capture inner error catch try exception throw
syntax: local function name(a, b) ... return x end   function(...) end   error("text")
lead: A function is a block of code you can call by name, with values passed in. return ends it and gives values back, several at once if you like. ... in the parameters takes any number of values: { ... } puts them in a list, select("#", ...) counts them, nils included. A function written inside another can still use that one's locals later (a closure): handy for handlers that need values from where they were made. Functions are values: store them in variables and tables and pass them to on{ }, run{ } and others. error("text") stops the code with a red message; pcall (its own page) catches it.
example:
  local function min_max(a, b)
    if a < b then return a, b end
    return b, a
  end
  local low, high = min_max(7, 3)       -- 3, 7

  local function sum(...)
    local total = 0
    for _, n in ipairs({ ... }) do total = total + n end
    return total
  end

  local function counter()              -- a closure
    local n = 0
    return function() n = n + 1; return n end
  end
  local next_number = counter()
  print(next_number(), next_number())   -- 1  2
expert: LuaJIT | a call that ends with return f(x) is a tail call: it doesn't grow the stack, so endless tail recursion is fine. Other recursion that never ends stops with a "stack overflow" error.
expert: Errors | error("text") adds the file and line in front; error("text", 0) doesn't. Lullaby shows it as the normal red error to ops and in the console.
expert: Cost | a call to a Lua function: guess 2–20 ns (not measured); a new closure: guess 50–300 ns plus garbage collection (not measured).
status: unconfirmed
]]

--[[doc
id: string_lib
name: string, table, math
kind: lua
group: Lua
also: table_lib math_lib
words: string upper lower sub find format rep gsub match split table insert remove sort concat join math random floor ceil abs min max sqrt round
syntax: s:upper()  s:sub(i, j)  s:find(x)  s:gsub(a, b)  string.format(f, ...)   table.insert(t, v)  table.remove(t, i)  table.sort(t, f)  table.concat(t, sep)   math.floor(x)  math.max(...)  math.random(a, b)  math.pi
lead: Lua's own functions for text, lists and math. Every string function can be called with : on a text; positions count from 1, negative ones from the end; find, match and gsub use Lua patterns, not regex. table.insert, remove and sort change a list, table.concat joins a list of texts into one text. math.random(a, b) gives a whole number from a to b, math.random() a decimal from 0 to 1.
example:
  local s = "Hello World"
  print(s:upper())                   -- HELLO WORLD
  print(s:sub(1, 5))                 -- Hello
  print(string.format("%d coins", 5))
  local names = { "c", "a", "b" }
  table.sort(names)
  print(table.concat(names, ", "))   -- a, b, c
  local roll = math.random(1, 6)
expert: Copies | every script file gets its own copy of string, table, math, coroutine and bit: adding string.trim in one file changes nothing in the others, and s:upper() always uses the original.
expert: LuaJIT | Lua patterns: %d digit, %a letter, %s space, . any, * + - ? repeats; % escapes. No | (or) and no {n} counts. table.sort is not stable and stops with an error when the compare function is inconsistent.
expert: Cost | most are fast C functions: guess 20–500 ns per call, more for long texts or lists (not measured). table.concat is the fast way to join many texts; .. in a loop is slow.
status: unconfirmed
]]

--[[doc
id: locked
name: locked libraries
kind: lua
group: Lua
also: io os ffi debug require
words: io os ffi debug require java sandbox unlock config file jit collectgarbage getfenv setfenv bytecode string table math copy
lead: For safety, io, os, ffi, debug and require (C modules) are locked: they don't exist in scripts. Each can be unlocked in plugins/lullaby/config.lua under unlock (io, os, ffi, debug, modules). unlock.java opens the Java door (its own page): any Java directly. unlock.debug also brings jit, collectgarbage, gcinfo, getfenv, setfenv and newproxy, because they reach into the Lua state every script shares. load and loadstring take Lua text only, never bytecode. print writes to the server console.
example:
  -- plugins/lullaby/config.lua
  return {
    unlock = { io = true },
  }
expert: Why | all scripts share one Lua state. io, os and ffi reach the machine (files, programs, memory); debug and getfenv/setfenv reach other scripts' locals and Lullaby's own tables. Bytecode is refused because broken bytecode can crash LuaJIT itself.
expert: Reload | config.lua is read again on /lullaby reload: a lock or unlock takes effect then.
status: unconfirmed
]]

--[[doc
id: metatables
name: metatables
kind: lua
group: Lua
words: metatable setmetatable __index __add operator class object
syntax: setmetatable(t, mt)   getmetatable(t)
lead: A metatable changes how a table behaves: __index for missing fields, __add and others for operators, __tostring for tostring. Needed for own classes; most scripts never need it. Lullaby's own values have hidden metatables.
example:
  local Point = {}
  Point.__index = Point
  function Point.new(x) return setmetatable({ x = x }, Point) end
  function Point:double() return self.x * 2 end
  print(Point.new(4):double())   -- 8
expert: Hidden | getmetatable on a Lullaby value (player, vec3, ...) gives false, not the table, so one script can't change how every script's players behave. setmetatable on them fails.
expert: LuaJIT | Lua 5.1 rules: __gc works only on userdata (not tables), __len is not used for tables, __pairs and __ipairs don't exist.
expert: Cost | a field found through __index: guess 5–30 ns (not measured); an __index function costs a full call each time.
status: unconfirmed
]]
