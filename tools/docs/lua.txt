Lua pages of the docs site (read by Docs.java, same block format as in lib/*.lua; each block names itself with id:).
Lullaby runs LuaJIT, which speaks Lua 5.1 (plus goto). A page whose id is a Lua keyword is linked from that keyword.

--[[doc
id: start
name: start here
kind: lua
group: Lua
words: begin first tutorial hello new
lead: A script is a .lua file in plugins/lullaby/scripts. Lullaby runs every file there on start and on /lullaby reload. Code at the top of a file runs once while loading; functions given to on{ }, after{ }, command{ } and run{ } run later, when something happens.
example:
  -- plugins/lullaby/scripts/hello.lua
  after{ "PlayerJoinEvent", function(e)
    message{ player = e.player, text = "Welcome!" }
    wait("2s")
    sound{ player = e.player, sound = "entity.player.levelup", source = "player", entity = e.player }
  end }
status: unconfirmed
]]

--[[doc
id: local
name: variables and local
kind: lua
group: Lua
words: variable var name assign global
syntax: local name = value
lead: A variable holds a value. local makes it belong to the block it is written in (a file, a function, an if, a loop); always use local. Without local it is a global of this script file.
example:
  local count = 0
  count = count + 1
  local a, b = 1, 2   -- several at once

--[[doc

name: nil, true, false
kind: lua
group: Lua
words: boolean null none empty bool
syntax: nil   true   false
lead: nil means "no value": unset variables and missing table fields are nil. true and false are the two booleans. In if and while, only nil and false count as false; 0 and "" count as true.
example:
  local p = player("Notch")
  if p == nil then print("not online") end

--[[doc
id: numbers
name: numbers and math
kind: lua
group: Lua
words: math plus minus divide modulo power arithmetic
syntax: + - * / % ^   == ~= < > <= >=
lead: Lua has one number type for whole numbers and decimals. % is the remainder, ^ the power. ~= means "not equal". Comparisons give true or false.
example:
  local half = 7 / 2      -- 3.5
  local rest = 7 % 2      -- 1
  local big = 2 ^ 10      -- 1024
  print(half ~= rest)     -- true
status: unconfirmed
]]

--[[doc
id: strings
name: strings (text)
kind: lua
group: Lua
words: text concat join length quote
syntax: "text"   'text'   [[many lines]]   a .. b   #s
lead: Text is written in double or single quotes. .. joins two texts, # gives the length. \n is a line break, \" a quote inside the text. In Lullaby a plain string is always literal text; component("<red>Hi") reads MiniMessage.
example:
  local name = "Steve"
  local hello = "Hello, " .. name .. "!"
  print(#hello)   -- 13
status: unconfirmed

--[[doc
id: tables
name: tables and lists
kind: lua
group: Lua
words: table list array map dictionary
syntax: { 1, 2, 3 }   { key = value }   t[k]   t.key   #t
lead: A table is Lua's only container. Written with numbers it is a list, counted from 1; with names it holds named fields. t.key is short for t["key"]. #t is the length of a list.
example:
  local list = { "a", "b", "c" }
  print(list[1], #list)        -- a  3
  local spawn = { x = 0, y = 64 }
  spawn.z = 0
  list[#list + 1] = "d"        -- add to the end
status: unconfirmed
]]

--[[doc

syntax: t.field   v:method(...)
lead: . reads a field. : calls a method on a value: v:offset(1, 0, 0) is short for v.offset(v, 1, 0, 0). In Lullaby, reading uses ( ), . and :, and doing uses { }.
example:

--[[doc

name: for (counting)
kind: lua
group: Lua
words: loop count number step
syntax: for i = first, last, step do ... end
lead: Counts i from first to last (both included). step is optional (default 1) and may be negative.
example:
  for i = 1, 3 do print(i) end        -- 1 2 3
  for i = 10, 1, -3 do print(i) end   -- 10 7 4 1

--[[doc
id: in
name: for ... in (lists and tables)
kind: lua
group: Lua
words: loop pairs ipairs each list table iterate
syntax: for i, v in ipairs(list) do ... end   for k, v in pairs(t) do ... end
lead: ipairs goes through a list in order (1, 2, 3, ...) and stops at the first nil. pairs goes through every field of a table, in no fixed order.
example:

    message{ player = p, text = "Hi #" .. i }
  end
  for key, value in pairs({ a = 1, b = 2 }) do print(key, value) end

--[[doc
id: varargs
name: ... (any number of values)
kind: lua
group: Lua
words: varargs variable arguments dots select
syntax: function f(...) local list = { ... } end
lead: ... in a function's parameters takes any number of values. { ... } puts them in a list; select("#", ...) counts them, nils included.
example:
  local function sum(...)
    local total = 0
    for _, n in ipairs({ ... }) do total = total + n end
    return total
  end
  print(sum(1, 2, 3))   -- 6

--[[doc
id: closures
name: closures
kind: lua
group: Lua
words: upvalue capture inner function
lead: A function written inside another can still use that one's local variables later, even after the outer function ended. Handy for handlers that need values from where they were made.
example:
  local function counter()
    local n = 0
    return function() n = n + 1; return n end
  end
  local next_number = counter()
  print(next_number(), next_number())   -- 1  2
status: unconfirmed
]]

--[[doc
id: pcall
name: pcall and error
kind: lua
group: Lua
words: error catch try exception throw
syntax: error("text")   local ok, result = pcall(f, ...)
lead: error stops the code with a message (Lullaby shows it in chat to ops and in the console). pcall calls a function and catches its error: ok is false and result is the message, instead of the script stopping.
example:
  local ok, err = pcall(function()
    error("something broke")
  end)
  if not ok then print("caught: " .. err) end
status: unconfirmed
]]

--[[doc

syntax: s:upper()  s:lower()  s:sub(i, j)  s:find(x)  s:rep(n)  s:gsub(a, b)  s:match(p)  string.format(f, ...)

--[[doc
id: locked
name: locked libraries
kind: lua
group: Lua
words: io os ffi debug require sandbox unlock config file jit collectgarbage getfenv setfenv bytecode string table math copy
lead: For safety, io, os, ffi, debug and require (C modules) are locked: they don't exist in scripts. Each can be unlocked in plugins/lullaby/config.lua under unlock (io, os, ffi, debug, modules). unlock.debug also brings jit, collectgarbage, gcinfo, getfenv, setfenv and newproxy, because they reach into the Lua state every script shares. load and loadstring take Lua text only, never bytecode. Every script file gets its own copy of string, table, math, coroutine and bit: adding string.trim in one file changes nothing in the others, and method calls like s:upper() always use the original string functions. print writes to the server console.
example:
  -- plugins/lullaby/config.lua
  return {
    unlock = { io = true },
  }
status: unconfirmed
]]

--[[doc
id: metatables
name: metatables
kind: lua
group: Lua
words: metatable setmetatable __index __add operator class object
syntax: setmetatable(t, mt)   getmetatable(t)
lead: A metatable changes how a table behaves: __index for missing fields, __add and others for operators, __tostring for tostring. Needed for own classes; most scripts never need it. Lullaby's own values have hidden metatables.
example:
  local Point = {}
  Point.__index = Point
  function Point.new(x) return setmetatable({ x = x }, Point) end
  function Point:double() return self.x * 2 end
  print(Point.new(4):double())   -- 8
status: unconfirmed
]]
